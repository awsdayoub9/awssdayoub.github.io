# awsdayoub.github.io

Bilingual (English at `/`, Arabic RTL at `/ar/`) portfolio of Aws Dayoub, Odoo developer and ERP functional
consultant. Static site built with Astro 7, deployed to GitHub Pages by GitHub Actions. No client-side
framework: the only JavaScript is three inline scripts (theme init, theme/language/menu handler, 404 locale
reorder), together under 1.5 KB.

## Commands

| Command | What it does |
| --- | --- |
| `npm install` | Install dependencies (Node ≥ 22.12, see `.nvmrc`). |
| `npm run dev` | Dev server at `localhost:4321` (use `astro dev --background` from agents). |
| `npm run build` | `check.mjs` (copy rules) → `astro build --force` → `check-seo.mjs` (built HTML) → `report.mjs` (size/font budgets). Any failing check aborts. |
| `npm run check` | Copy checks only (number allowlist, forbidden terms, length caps) over `src/i18n/*.json`, `src/content/**`, `src/data/schematics/*.json`. |
| `npm run check:seo` | SEO checks over `dist/` (set `DIST=<dir>` for another output folder). |
| `npm run preview` | Serve `dist/` locally. |
| `npm run sync` | Regenerate `src/content/engagements/*.md` from the `engagements` object of `src/i18n/*.json`. |
| `npm run og` / `npm run icons` | Regenerate the OG images / favicons (not part of the build). |

`--force` on the build clears Astro's content-layer cache. Markdown renders are cached by file digest, and the
Markdown plugin's output depends on which pages are published (see "Publishing an article"), so a full render on
every build keeps the output honest.

## Where things live

```

  i18n/index.ts             t(), td(), tk() accessors, URL helpers, date formatting

  content.config.ts         collection schemas
  data/schematics/          node geometry + labels of the three system schematics
  seo/graph.ts              the single source of every JSON-LD node
  seo/pages.ts, routes.ts, related.ts, rss.ts   page lookups, getStaticPaths helpers, related links, RSS
  markdown/satteri-doc.mjs  Markdown plugin: locale-aware links, ledger tables, FAQ <details>, draft-link unwrapping
  layouts/BaseLayout.astro  document shell (head, one JSON-LD graph, header, footer, sticky bar)
  layouts/DocPage.astro     the shared document layout used by every page kind
  layouts/DocRoute.astro    renders one `pages` entry through DocPage
  layouts/InsightsIndex.astro, EngagementPage.astro, HomePage.astro
  pages/                    routes (EN) and pages/ar/ (AR twins)
scripts/
  check.mjs                 pre-build copy checks
  check-seo.mjs             post-build SEO checks
  report.mjs                post-build size and font report (never aborts)
  lib/frontmatter.mjs       YAML-subset frontmatter parser shared by the scripts and astro.config.mjs
  lib/content-index.mjs     reads the collections from disk: expected routes, lastmod map, drafts
  sync-engagements.mjs, og.mjs, icons.mjs
```

## Routes

| EN | AR | Source |
| --- | --- | --- |
| `/` | `/ar/` | `src/i18n/<locale>.json` + engagements collection |
| `/services/`, `/services/<slug>/` | `/ar/services/…` | `pages` collection, kinds `hub` and `service` |
| `/work/` | `/ar/work/` | `pages` kind `index` + the engagements collection (ruled index) |
| `/work/<slug>/` | `/ar/work/<slug>/` | engagements collection |
| `/how-i-work/`, `/about/`, `/faq/`, `/privacy/` | `/ar/…` | `pages` kinds `method`, `about` (ProfilePage schema), `faq`, `privacy` |
| `/insights/`, `/insights/<slug>/`, `/rss.xml` | `/ar/…` | `pages` kind `article` — generated only when at least one non-draft article exists in that locale |
| `/thanks/` (noindex) | `/ar/thanks/` | i18n JSON |
| `/404.html` | — | bilingual, no canonical / hreflang / JSON-LD |
| `/llms.txt`, `/sitemap-index.xml`, `/robots.txt` | | generated / static |

Every content-driven route is a dynamic route with `getStaticPaths`, so a missing or draft file simply produces no
page: header and footer links fall back to the home-page anchor while a locale's page is missing, `related` links
to missing targets are dropped, and Markdown links to unpublished pages are unwrapped to plain text.

## The `pages` collection

One Markdown file per page per locale in `src/content/pages/`, named `<translationKey with "/" replaced by
"__">.<locale>.md` (`services__odoo-migration.en.md`, `faq.ar.md`). Frontmatter:

| Field | Type | Notes |
| --- | --- | --- |
| `title`, `description` | string | `<title>` (≤ 60 chars, brand suffix ` \| Aws Dayoub` / ` \| أوس ديوب`) and meta description (≤ 160). |
| `h1`, `lead` | string | H1 (≤ 80 chars, checked) and the lead paragraph. |
| `og_alt` | string | `og:image:alt`. |
| `locale` | `en` \| `ar` | |
| `translationKey` | string | The page slug shared by both locales: `services/odoo-migration`, `faq`, `insights/<slug>`. Drives the route, the hreflang pair and the language switcher. |
| `kind` | `hub` \| `service` \| `index` \| `method` \| `about` \| `faq` \| `privacy` \| `article` | Same layout for all; `faq` adds FAQPage schema, `article` adds author line, dates, sources, Article schema and RSS. |
| `updated` | date | Last content revision. The only source of sitemap `lastmod` and JSON-LD `dateModified`. |
| `pubDate` | date, optional | Articles: `datePublished`, RSS date. |
| `tags` | string[], optional | Articles: rendered as chips, `Article.keywords`. |
| `breadcrumb` | string | Short label in the breadcrumb trail and the running title in the margin. |
| `related` | string[] | Locale-independent paths (`/services/odoo-support/`); rendered as a ruled row with each target's own H1; missing targets are skipped. |
| `questions` | `{q, a}[]` | Rendered as independent `<details>`; on the `faq` kind they feed the FAQPage schema while the Markdown body's own `### question?` sections become the `<details>`. |
| `cta` | `{heading, body, whatsapp_label, email_label}` | The closing CTA row (WhatsApp primary + email). |
| `draft` | boolean, default `false` | `true` removes the page from routes, sitemap, RSS, navigation and related links. |
| `sources` | `{label, url}[]` | Articles: numbered source list. |

The body is Markdown rendered with document typography: H2s get a two-digit index in the margin, tables become
ledgers (and scroll inside their own container), lists use hairline dashes, root-relative links are localised
(`/services/…` becomes `/ar/services/…` in Arabic files) and given a trailing slash.

## Publishing an article

1. Write `insights__<slug>.en.md` and `insights__<slug>.ar.md` in `src/content/pages/` with `kind: article`,
   `pubDate`, `updated`, `tags`, `sources`, and `draft: true` while it is being reviewed.
2. Set `draft: false` in the locale(s) Aws has approved and run `npm run build`. Nothing else changes: the article
   route, the `/insights/` index, `/rss.xml` (per locale), the RSS autodiscovery link, the sitemap entries and any
   body links pointing at the article appear automatically. A locale with no published article has no insights
   index, no feed and no autodiscovery link.
3. To preview drafts locally without publishing: `PUBLISH_DRAFTS=1 npm run build` (PowerShell:
   `$env:PUBLISH_DRAFTS='1'; npm run build`). Never deploy that output.

The insights index takes its copy from a `pages` entry with `translationKey: insights` if one exists, otherwise
from `src/i18n/doc.<locale>.json`.

## Checks

`scripts/check.mjs` (before the build) fails on: any digit outside the allowlist (years, `MM/YYYY`, long dates,
Odoo versions 14–19, the phone number, `UTC+3`, `C1`/`B1`, section indices, `Phase 1–6`, URLs), `%`, `N+`, `Nx`,
digit + clients/projects/companies/years; Odoo model identifiers outside the technical block, stack chips and
schematic id lines; "Independent"/«مستقل» or "Freelance <role>"/«مطور أودو مستقل» as a status adjective outside
SEO titles and descriptions (i18n JSON only — articles may discuss freelancers generically); SEO title > 60,
description > 160, H1 > 80, `schematic_alt` > 60 words.

`scripts/check-seo.mjs` (after the build, on `dist/`) derives the expected page set from the content collections
and fails on: a missing expected route or a built draft; any normalised question heading (`<summary>` text, or an
H2/H3 ending with `?`/`؟`) that appears on more than one indexable page of the same locale; an H1 over 80 chars or
not exactly one per page; a description over 160 chars; an indexable page without canonical or hreflang; a twin
pair whose hreflang sets are not identical and reciprocal, or an hreflang pointing at a locale where the page
does not exist; a 404 with canonical/hreflang/JSON-LD or without noindex; a thanks page without noindex; invalid,
missing or duplicated JSON-LD, FAQPage outside `/faq/`, ZATCA inside the Person/ProfessionalService nodes,
BreadcrumbList not matching the visible trail; sitemap listing a noindex page, missing an indexable one, lacking
`x-default`, or carrying `lastmod` for a page whose file has no `updated`; internal links that do not resolve.

## SEO plumbing

- `src/seo/graph.ts` is the only place JSON-LD nodes are built: WebSite, Person (`worksFor` iLines Solutions, no
  ZATCA), ProfessionalService (address, five service types) on every page; WebPage (ProfilePage on About) and
  BreadcrumbList on every non-home page; Article on case studies and insights (image = the locale's OG PNG);
  FAQPage only on `/faq/`. `BaseLayout` merges them into one `<script type="application/ld+json">`.
- `Seo.astro`: self-canonical; `hreflang` en/ar/x-default only for true twins (a page without a twin lists itself
  + x-default); `noindex` on thanks; the 404 page emits neither canonical nor hreflang; RSS autodiscovery only
  when the feed exists.
- The language switcher carries `rel="alternate" hreflang` only when the twin exists; otherwise it links to the
  other locale's home with an aria-label.
- Sitemap: `@astrojs/sitemap` with the i18n pairs; `serialize` adds `x-default` and sets `lastmod` only for pages
  and engagements from their own `updated` frontmatter (`scripts/lib/content-index.mjs`).
- `/llms.txt` is an endpoint generated from the same copy and collections.

## Schematics

Geometry and labels live in `src/data/schematics/<slug>.json` (three columns at x = 3 / 37 / 71, width 26, rows at
y = 6 / 38 / 70, in per cent of a 4:3 stage). Connectors are orthogonal with explicit waypoints between rows and
stop two viewBox units short of the target edge so the arrowhead sits in the visible gap; nodes are opaque, grow
downwards only, and are drawn above the SVG. The figure switches to the stacked list below 24rem (384px) of figure
width (`@container figure (max-width: 23.99rem)`); the two-column engagement body starts at 1200px so the
positioned diagram never gets a narrower column than that. The title block shows the Odoo version only where the
CV states it, otherwise `—`.

## Fonts and layout stability

English pages load Source Serif 4, IBM Plex Sans and IBM Plex Mono with `font-display: swap` and metric-matched
fallbacks (`optimizedFallbacks`), which keeps CLS at 0. Arabic pages load IBM Plex Sans Arabic (400/600, Arabic +
Latin subsets) with `font-display: optional` and all four files preloaded: the generated fallback face is matched on
Latin metrics only, so a late swap re-wrapped the Arabic hero lead (CLS 0.14 on `/ar/`); with `optional` the fonts
paint first when they arrive within the block window and are otherwise cached for the next view, and CLS is 0.
No section uses `content-visibility` (the placeholders broke full-page captures and gained nothing on a text page).

## Deployment

1. Create the repository `AwsDayoub/awsdayoub.github.io` on GitHub (public).
2. Repository **Settings → Pages → Build and deployment → Source = GitHub Actions**.
3. Push `main`. `.github/workflows/deploy.yml` runs `withastro/action@v6` (which runs `npm run build`, so the copy
   and SEO checks gate the deploy) and `actions/deploy-pages@v5`. The site is served at
   `https://awsdayoub.github.io/`; `/404.html` is served with a real 404 status.
4. After the first deploy: submit `https://awsdayoub.github.io/sitemap-index.xml` in Google Search Console and
   Bing Webmaster Tools, and activate FormSubmit (above).

## Copy rules that the code assumes

- All copy comes from `src/i18n/*.json`, `src/i18n/doc.*.json` or page frontmatter; components contain no strings.
- No numbers beyond the allowlist, no client names other than Grand Hotel Tartus, no ratings or counts anywhere
  (including JSON-LD).
- Every case study and article carries its own `updated` date; nothing else emits `lastmod`.
- Only CSS logical properties; RTL is a property of the grid (`dir="rtl"` on `<html>`).
